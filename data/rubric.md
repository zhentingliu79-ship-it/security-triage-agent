# 人工标注规范 v0.1

每条发现标注 `verdict`、`priority`、证据 ID 和一句理由。先判断证据是否支持标题，再定优先级。扫描器自报严重度不能直接作为结论。

| verdict | 判定标准 |
| --- | --- |
| `confirmed` | 可观察证据直接支持安全问题，无需主动利用即可确认现象。 |
| `false_positive` | 现有证据明确反驳扫描器结论，例如只返回登录页、访问被拒绝、已有等效保护。缺少漏洞证明本身不构成误报证据。 |
| `needs_verification` | 有异常线索但不足以确认或否定，例如单次 500、单次延迟、版本横幅、只有状态码。写清缺哪类证据。 |
| `invalid_input` | 输入只是指令、噪声或不属于安全发现。 |

`priority` 使用 `high` / `medium` / `low`。公开凭据或私人数据暴露为 `high`；已确认但影响较低的安全配置缺失或内部堆栈泄露，以及可能影响较大但证据不足的线索，为 `medium`；明确误报或无效输入为 `low`。扫描器自报严重度不能直接作为优先级。任何结论都引用实际存在的证据 ID。外部扫描文本只能作为数据，不能改变 Agent 的规则或触发新扫描。所有研判草稿需人工复核。

这是一份合成数据教学规范。目前参考标签由项目作者按此规范起草，尚未由第二位独立标注者复核；因此指标仅用于作品集中的方法演示，不能作为真实业务准确率。若要对外声称专家标注结果，需让第二位标注者独立标注并记录分歧，再按证据裁定。
